# 中国软件著作权（软著）登记材料助手

> **边界**：协助整理登记材料与格式，**不替代**代理机构/中国版权保护中心审核。栏目名称与装订要求以 [中国版权保护中心](https://www.ccopyright.com.cn/) 当前通知为准。

相关：专利申请 → `patent-drafting`；合同审核 → `contract-review`。

## 何时用软著 vs 专利

| 目标 | 优先 |
| --- | --- |
| 证明软件权属、招投标/高新/版号常用材料 | **软著** |
| 保护技术方案本身（方法/结构） | **专利**（`patent-drafting`） |
| 两者都要 | 先固化权属与交底，再并行准备；注意开源协议义务 |

## 材料清单（常见）

| 材料 | 说明 |
| --- | --- |
| 申请表 | 在线填写后打印签章（以当前系统为准） |
| 软件鉴别材料 — 源程序 | 通常提交连续前、后各 30 页（不足 60 页则全文）；每页不少于 50 行（末页除外） |
| 软件鉴别材料 — 文档 | 操作说明书/设计说明书等，通常前、后各 30 页或全文 |
| 身份证明 | 个人身份证 / 企业营业执照等 |
| 权利归属证明 | 职务开发证明、合作开发协议、转让证明等（按情形） |

具体页数、封面、右侧装订线等细节见 [`references/materials-checklist.md`](references/materials-checklist.md)。

## 工作流

```text
确认软件全称/简称/版本/开发完成日
  ↓
确认权利范围与开发方式（独自/合作/职务/继受）
  ↓
整理源码导出规范（语言、目录、去密钥）
  ↓
生成操作说明书大纲并扩写
  ↓
按页规则截取鉴别材料 + 页眉页脚
  ↓
填写申请表字段对照表
  ↓
自检 → 提交人或代理机构
```

### 1. 命名与元数据

- **全称**：宜含软件用途，避免纯英文无中文说明（按中心习惯）
- **简称**：可空；若填须与全称对应
- **版本号**：如 `V1.0`，与材料封面一致
- **开发完成日期** ≤ **首次发表日期**（未发表可填“未发表”）
- **权利取得方式**：原始取得 / 继受取得

模板：[`references/application-fields.md`](references/application-fields.md)

### 2. 源程序鉴别材料

1. 导出可读源码（去 `.env`、密钥、证书、客户数据）
2. 按统一等宽字体排版；页眉建议含：软件全称 + 版本号
3. 页脚：页码  
4. 取**连续**前 30 页 + 后 30 页；总行数不足则提交全部  
5. 标注“本软件源程序前/后 30 页”类封面（按代理模板）

脚本辅助（可选）：[`scripts/extract_source_pages.py`](scripts/extract_source_pages.py)

### 3. 文档鉴别材料（操作说明书）

最低应让审查员看懂：**运行环境、安装/部署、主要功能与操作步骤、界面说明**。

大纲：[`references/manual-outline.md`](references/manual-outline.md)

### 4. 自检

- [ ] 全称/版本/日期在申请表、源码页眉、说明书封面一致  
- [ ] 源码无密钥与客户隐私  
- [ ] 页数与行数规则满足当前要求  
- [ ] 权利人名称与证件一致  
- [ ] 开源组件清单与许可证允许登记声明（内部备忘）

## 输出交付物

默认目录：`软著材料_{软件简称}/`

| 文件 | 内容 |
| --- | --- |
| `00_元数据.md` | 全称、版本、日期、权利人 |
| `01_申请表字段.md` | 对照填写 |
| `02_操作说明书.md` | 完整说明书文稿 |
| `03_源码截取说明.md` | 目录、截取范围、排版参数 |
| `04_权利归属备忘.md` | 职务/合作/委托关系 |

## 禁止

- 用无关开源项目冒充自有软件登记  
- 篡改开发完成日期作假  
- 在鉴别材料中保留生产密钥或个人敏感信息
