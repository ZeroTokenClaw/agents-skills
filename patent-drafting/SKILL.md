# 中国专利撰写助手

> **边界**：辅助工程师整理交底与初稿，**不替代**专利代理师/律师意见，不保证授权。正式提交以代理机构与国知局审查为准。

相关：合同条款 → `contract-review`；法条结构化 → `law-to-markdown`；软著登记 → `software-copyright-cn`。

## 选型

| 需求 | 类型 | 保护对象 | 周期粗估 |
| --- | --- | --- | --- |
| 技术方案、方法、系统、算法落地装置 | **发明** | 产品/方法 | 较长，实质审查 |
| 产品形状/构造或其结合 | **实用新型** | 产品结构 | 较短，初审为主 |
| 产品外形、图案、色彩或其结合 | **外观设计** | 外观 | 较短 |

算法本身通常不宜单独作为“纯智力活动规则”；写成 **技术问题 + 技术手段 + 技术效果** 的方案（含硬件/数据流/控制步骤）再布局。

## 工作流

```text
需求澄清
  ↓
技术交底书（references/disclosure-template.md）
  ↓
可专利性粗判（客体 / 新颖性 / 创造性 / 实用性）
  ↓
现有技术对比表（至少 2–3 篇对比文件维度）
  ↓
权利要求布局（独权 → 从权树）
  ↓
说明书全文 + 附图说明
  ↓
自检清单 → 交付代理机构润色/提交
```

### 1. 澄清（必问，缺则补问）

- 要解决的**技术问题**与现有痛点
- 核心创新点（相对最接近现有技术差在哪）
- 产品形态：装置 / 方法 / 系统 / 介质；是否有实物结构
- 已公开渠道：论文、开源、销售、展会、宣传页（影响新颖性）
- 目标：国内发明 / 实用新型 / 外观 / 是否考虑 PCT 或优先权

### 2. 技术交底

使用模板：[`references/disclosure-template.md`](references/disclosure-template.md)

要求：背景、现有技术缺陷、发明目的、技术方案（可复现粒度）、关键参数/流程、实施例 ≥2、有益效果、替代实施方式。

### 3. 权利要求布局原则

- **独立权利要求**：必要技术特征完备；避免纯效果措辞；术语前后一致
- **从属权利要求**：逐层增加优选特征（参数范围、模块细化、步骤细化）
- 方法 + 装置可考虑 **多独权** 布局（同日申请策略需代理确认）
- 禁止在独权中塞入非必要的过窄参数（除非该参数即发明点）

结构骨架见 [`references/claims-skeleton.md`](references/claims-skeleton.md)。

### 4. 说明书结构（发明/实用新型）

1. 发明名称  
2. 技术领域  
3. 背景技术（客观，勿贬损）  
4. 发明内容（问题、方案摘要、有益效果）  
5. 附图说明  
6. 具体实施方式（与权利要求支撑对应；实施例可覆盖从权特征）  
7. 必要术语定义  

### 5. 自检清单

- [ ] 独权能否单独实施并解决所述技术问题  
- [ ] 每个从权特征在说明书有支撑  
- [ ] 附图标记与说明书一致  
- [ ] 无商业宣传用语、无未定义缩写  
- [ ] 公开日风险已标注（自己或他人公开）  
- [ ] 与软著/开源协议无冲突说明（如有）

## 外观设计要点

- 明确产品名称、设计要点、视图套（六视图/立体图等按代理要求）
- 保护“外观”而非功能原理；避免纯功能性形状描述过多

## PCT / 海外（概要）

- 国内优先权通常 12 个月；具体期限以代理为准
- 本 skill 只出策略问题清单，不生成各国格式文本

## 禁止

- 伪造对比文件结论或“保证授权”
- 协助规避已有权利的仿冒方案包装
- 将他人论文/开源代码改写后谎称自有发明且隐瞒来源
